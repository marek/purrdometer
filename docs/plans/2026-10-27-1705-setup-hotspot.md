# Setting up from a phone: the setup hotspot

Date: 2026-10-27 17:05 EDT

## Context

A freshly flashed purrdometer with no WiFi configured, or one whose owner
asks for it, should be set up from a phone with no keyboard, screen or
Imager. Setup never starts because a configured WiFi is unreachable: a router
that is down for a while must not push the Pi off the network for good. The
owner asks for setup at boot: while the screen program starts, it shows a
WiFi icon to hold for a few seconds, which a stray touch cannot do by
accident. In the manner of Pi-Star's Auto AP, it starts its own WiFi hotspot;
unlike a fixed or open hotspot, the password is random and made on the
device, and the e-paper screen shows the hotspot's name, password and the
setup address (as a QR code too), so only someone at the wheel can join. The
setup page chooses the WiFi network and its password, sets the login user's
password (and optionally SSH), and the wheel. There is no default user and no
default password anywhere. The WiFi that worked stays until a new one has been
saved and joined, and setup mode that nobody uses ends after a timeout, so a
setup that fails or was started by mistake returns to the network the Pi was on.

Constraints: NetworkManager runs the hotspot (shared mode); its DNS answers
every name with the Pi so a phone opens the setup page by itself; the Pi Zero
2 W cannot hold a hotspot and a WiFi connection reliably at once, so networks
are scanned before the hotspot starts; changing WiFi and passwords needs root,
so a small privileged helper does that and the web server stays unprivileged.

## Tasks

- [ ] Intent: when setup mode starts and ends, the hotspot, the screen, the page, the helper's boundary
- [ ] Setup mode starts only on a first boot with no WiFi configured, or when the WiFi icon on the boot screen is held; never because WiFi is unreachable
- [ ] The hotspot with a per-device random password, through NetworkManager; DNS answering with the Pi
- [ ] The e-paper setup screen: hotspot name, password, address, QR code
- [ ] The setup page: networks scanned before the hotspot, WiFi password, login password, SSH, wheel
- [ ] The privileged helper for WiFi and passwords, and nothing else
- [ ] Setup ends: join the chosen WiFi and show the new address; on failure, or after a timeout with no setup, return to the WiFi configured before
- [ ] Besides the boot hold, a way into setup while running: a "Start WiFi setup" button on the web gear page, a long press on the current tab opening an e-paper settings screen, both, or neither (the user to decide)
- [ ] Tests for what runs without a radio; the rest on whiskerwheel
- [ ] Joining the hotspot from a phone opens the setup page, and setup gets the Pi onto the home WiFi (the user)
